Product plan and core values

Once you approve this section, the core values are fixed. They go into PRINCIPLES.md and every future feature plan is checked against them. If a feature breaks one, the feature changes, not the value.

What makes it unique

One keystroke swaps your whole context on Windows. The windows, layout and distractions of one task step aside, the next task's come back exactly as you left them, and you never had to file anything.

Close relatives, and what they miss: Windows virtual desktops switch in order instead of by name, never launch a fresh workspace, and can't block anything. PowerToys Workspaces launches app layouts but forgets your session the moment you leave it. Cold Turkey / Freedom only block. FancyZones only arrange. Catogarizer is the one tool where switching, restoring, launching and blocking are the same action.

Core values

Nothing is ever lost

Catogarizer hides windows, it never closes them. Every hidden window can be found in one step, and all of them come back when Catogarizer exits, crashes or updates.

Decision rule: a feature that can leave a window unreachable is rejected. Closing always needs an explicit per-app action.

Switching is the product

A switch feels instant. Restoring a session shows no spinner and no overlay. Editing, settings and automation never slow down or clutter the switch path.

Decision rule: measure it. Hotkey to restored windows under 300 ms on this machine.

Keyboard first, mouse welcome

Any switch takes the hotkey plus at most two keys. Every action you do more than once a day has a key, and every key action also has a visible mouse path.

Decision rule: no feature ships with only one of the two paths.

Zero bookkeeping

You never maintain sessions. A window joins the active category by appearing. Templates change only when you say so, so they never fill up with one-off clutter.

Decision rule: if a feature needs the user to tidy up regularly, redesign it.

Glance, don't study

The home answers "where am I, what's parked where, what's held back" in two seconds. No thumbnails, no charts for the sake of charts, no live previews.

Decision rule: if information doesn't help decide where to go next, it moves one level deeper.

Quiet by default

It runs all day at close to zero idle CPU. It only speaks when it acted for you (an app was held back, a trigger switched). No streaks, no guilt, no nagging.

Decision rule: every notification must name an action Catogarizer already took.

Yours, local, no admin

No account, no cloud, no telemetry, no elevation. The config is a readable JSON file on your disk.

Decision rule: a feature that needs admin rights or a server is out, however useful.

Orange rows are my assumptions. Please look at those first, they're where I might have misread you.

GUESSED

Safety net for hidden windows. On exit, on crash and on the next start, every window Catogarizer hid is shown again. The tray gets "Show all hidden windows".

Hidden windows vanish from the taskbar and Alt-Tab. If the app crashes without this, you'd think your work is gone. Solution: write hidden handles to hidden.json on every hide, restore at exit and startup.

GUESSED

Each category gets a color, auto-assigned and changeable.

Makes the active category recognizable in the palette, tray, home and switch feedback without reading. Additive model change (Category.Hue).

GUESSED

Remember the previous category so "go back" is one action.

Back-and-forth is the most common switch. Needed by every design and by signature moment A.

GUESSED

Real app icons extracted from the exe, cached, with a letter tile as the loading/fallback state.

Icon stacks are only faster than names if they're the real icons.

GUESSED

The UI stays English and the implicit category is called Unsorted (the concept calls it "Sonstiges").

Mixing one German label into an English UI reads like a bug. See question 2.

Signature moment (pick one)

One moment that is deliberately better than it needs to be. Only one, so it stands out. Once chosen, it's off-limits for cleanup and "consistency" passes.

Why A: it's used dozens of times a day, and it's the one thing virtual desktops can't do. B and C would still exist in a plain form (a "create from open windows" button, a basic switch toast), just without the extra care.

Build plan

One branch, feature/v2-switching-ui, one commit per step, tests before every commit. The order is set by risk: the safety net comes first because hiding windows without it is dangerous, and the signature moment comes early so it doesn't get built tired.

Safety net and session state (Core, test-first)

Persist hidden windows and restore them on exit and startup. Extend the switch service with ActiveCategoryChanged, PreviousCategoryId, active-since time and a session snapshot (count + titles per category). Fixes the known 350 ms attribution race while I'm in there.

xUnit + fakesreal-app check: kill process while hidden, restart

Wire switching into the running app

Composition root, tray menu, palette, CLI (catogarizer switch "Deep Work"), blocking follows the active category, trigger action "Open category" becomes a switch. The old category-level Open/Close/Minimize goes away; per-app actions stay.

Built right after switching works, not at the end. For A: double-tap detection in GlobalHotkeyService, a borderless click-through pill window with a short WPF storyboard.

Two questions

1. One theme, or a theme setting?

Should the app ship with the one theme you pick, or should Settings let you switch between all of them?

My guess: a Settings choice. With the token split in build step 4 each extra theme costs almost nothing, and a sellable product usually has at least a light and a dark option. Your pick becomes the default.

2. English UI with "Unsorted"?

The app is English today, but the concept calls the implicit category "Sonstiges".

My guess: stay English and call it "Unsorted". A German UI would be a separate, later decision for the whole app.
